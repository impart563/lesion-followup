# 离线复核工作区

工作区把测量整理、记录核查、报告和草稿放在四个独立视图中。界面使用
MoonBit 核心完成解析与计算；浏览器负责选择文件、编辑文本、展示结果和保存草稿。
内置示例均为合成数据，结果只涉及靶病灶。

## 启动

在仓库根目录执行：

```sh
python scripts/build_browser.py
```

构建结果位于 `_build/browser/`。需要用本地 HTTP 服务打开，浏览器通常不允许从
`file:` 地址载入 ES 模块。Windows 可在仓库根目录运行：

```sh
python -u -c "import http.server,socketserver; server=socketserver.TCPServer(('127.0.0.1',8765),http.server.SimpleHTTPRequestHandler); server.serve_forever()"
```

随后打开 `http://127.0.0.1:8765/_build/browser/`。Linux/macOS 也可直接服务构建目录：

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory _build/browser
```

所有运行资源都来自本地构建目录，没有在线字体、CDN 或远程计算服务。页面的
`connect-src 'none'` 限制主动网络连接。草稿与本地服务的来源地址关联，更换端口、
浏览器或用户配置后，不会自动共享同一份本机草稿。可通过草稿文件转移进度。

## 从测量到报告

1. 点击“导入记录”，选择同一研究的 JSON 配置与 CSV 随访文件；也可先查看合成示例。
2. 在“测量记录”中编辑观察。基线资料按需展开；随访筛选只改变显示范围，不改变顺序或参与计算的记录。
3. 到“记录核查”查看待修正项和人工核查项。定位按钮会返回对应单元格或原始文件。
4. 检查通过后生成报告。界面展示靶病灶分类分布、总和趋势和参照值；完整报告保留每次测量与逐条件计算依据。
5. 按需导出输入、五种格式的报告，或准备摘要与完整证据打印视图。

CSV 的引号、换行和多行说明由现有 MoonBit 解析器处理。表格中的直径保持文本值，
不会四舍五入或把缺失值写成零。编辑会同步更新原始 JSON/CSV；保留内容与顺序，
不保证原文件的缩进、引号风格或换行编码保持不变。

格式可读但临床记录有误时，表格会保留有问题的值供修正。JSON 语法/字段类型，或
CSV 引号、表头、列数有误时，原文仍会保留，可以直接编辑后更新表格。人工核查项
与待修正项分开显示；NE 可以来自有效输入，不会被改成解析错误。

修改输入、恢复草稿或切换报告语言后，之前的报告和打印视图会立即撤下。重新生成后，
导出、趋势和打印均使用当前记录。异步读文件或生成输入标识期间发生的新修改，也不会
被旧操作的结果覆盖。

## 保存与恢复

右上角“保存草稿”只在点击时写入本机，不会自动保存。草稿可包含尚未通过检查的输入。
刷新或再次打开页面后，在“草稿”中点击恢复。清除操作仅删除本工作区的专用草稿键，
不修改当前正在编辑的记录，也不清空其他网站或应用的数据。

草稿文件使用独立的版本化 JSON 容器，保留研究原文、CSV 原文、报告语言和保存时间。
容器必须完整且版本受支持，才会替换当前输入；损坏或不兼容的文件会给出提示，当前
记录和报告保持不变。载入有效容器后，内容仍要经过原有的记录核查。

草稿保存在浏览器的本地存储中，并非加密的病例管理系统。工作区示例和验收均使用
合成记录；实际使用者需自行管理设备、浏览器配置与文件的访问范围。

## 打印与追溯

“摘要打印”和“完整证据打印”在页面内打开预览，无需弹窗或外部页面。
确认后使用打印按钮，或按 Ctrl+P；也可下载独立打印 HTML 后使用浏览器打印。

两种布局使用相同的研究编号、基线日期和当前输入 SHA-256 标识。标识是研究原文与
CSV 原文组成的有序字符串数组经 JSON 编码后的 UTF-8 字节摘要；它用于对应这次输入，
与报告包中原始文件字节摘要的表示方式不同。摘要屏幕视图可以跳转到同次完整证据，
打印稿保留研究信息和标识，便于与完整稿逐项对照。

布局按 A4、12 mm 页边距设计。摘要仅打印随访汇总；完整稿包括趋势、测量台账、
原始观察、计算条件和范围说明。长表格允许分页并重复表头；长说明可换行，SVG 在页宽内缩放。
操作区和编辑控件不进入打印内容。不同浏览器或打印机可能使用不同字体与分页策略，
打印前仍可在系统预览中确认纸张与缩放设置。

## 设计与验收

信息结构参考了 [Linear 项目工作区](https://linear.app/docs/projects) 的分区与上下文组织，
以及 [Stripe 的界面设计指南](https://docs.stripe.com/stripe-apps/design) 对主要操作、详情视图
和一致组件的处理方式。导航、图标、样式与文案均在本仓库实现，没有引入第三方运行依赖。

自动验收命令为 `python scripts/acceptance.py`。除原有四后端核心测试与 CLI 对比外，
还覆盖编辑后导出重读、多行 Unicode CSV、无效值保留、草稿版本、输入标识独立校验、
打印证据链接和 36 次随访的长记录。浏览器与分页检查记录见 [验收说明](acceptance.md)。
